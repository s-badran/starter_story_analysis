## 1. The Spark - What is Cursor?

**Context:**
Cursor is an AI code editor (built on VS Code, powered by Claude). It allows developers to write code faster using AI assistance.

**The Problem Cursor Directory Solves:**
Cursor has a ".cursor" rules feature—essentially custom AI prompts that control how Claude behaves for different programming scenarios.

Users created thousands of rules/prompts but had no centralized place to:
- Discover new rules
- Share their own
- Search for rules by programming language
- Rate rules
- See what others were using

---

## 2. The Discovery - Finding the Opportunity

**How They Found It:**
Pontus and Victor were using Cursor. They noticed the community was creating amazing rules but scattered across GitHub, Twitter, Discord.

**The Realization:**
"There's a need here. People want to see what rules others are using. There's no centralized place."

**Initial Assumption:**
"This would be a big build... we'll probably spend a few months on it."

## 3. The MVP - Built in 3 Hours

**Actual Timeline:** Weekend project, literally 3 hours

**Decision Point:**
Rather than build the "perfect" directory with many features, they shipped the minimum:
- List of cursor rules
- Upload/submit functionality
- Basic search
- Simple design (but good design—Victor's expertise)
- No authentication required (friction elimination)

**Tech Stack:**
- Frontend: Next.js (React framework)
- Backend: Simple setup
- Database: Minimal
- Hosting: Vercel or similar
- Payment: Stripe (simple integration)

**Why So Fast:**
1. Very narrow scope (JUST a directory, nothing else)
2. Leverage existing tech (Next.js, Vercel)
3. Simple design (Victor designed, didn't overcomplicate)
4. MVP philosophy (ship fast, iterate after launch)

## 8. The Design Competitive Advantage

**Core Thesis from Victor:**
"In an AI-generated world, design becomes MORE important, not less."

**Why:**
- AI can generate content (rules, code, text)
- But AI cannot generate elegant design
- Design is defensible in a world of commoditized content

**Cursor Directory Design Principles:**
1. **Simple navigation** - Find rules in 2 clicks
2. **Visual hierarchy** - Clear what's important
3. **Trust signals** - Ratings, downloads, creator info
4. **Responsive design** - Works on mobile (important for browsing during coding)
5. **Micro-interactions** - Smooth, pleasant experience

**The Result:**
Directory looked professional vs. competitors' (if any existed). This design quality was marketing. People felt confident sharing it.

## 12. Network Effects

**How Network Effects Work:**

**Growth Loop:**
1. Engineer submits their Cursor rules to directory
2. Directory becomes more useful (more rules to choose from)
3. More engineers visit directory
4. More engineers discover useful rules
5. More engineers submit their own rules
6. Loop amplifies

**Viral Coefficient:**
Each rule submission brought 2-3x more traffic than the rule itself would suggest.

**Why:**
- Rule creators shared link with their networks
- Rules became popular on Twitter/Reddit
- Directory gained SEO value (search "best cursor rules")
- Network strengthened
